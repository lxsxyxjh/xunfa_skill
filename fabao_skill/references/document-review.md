# 法律文书快速检查

按照“法条错误、错别字、病句、结构错误、序号错误、事实错误、论述错误”的优先级完成一次有限检查。只输出确定错误，不输出正确内容、检查过程、工作日志或重复建议；本页输出规则优先于 `SKILL.md` 的通用法律分析输出规则。

## 强制执行路径

1. 用户直接粘贴文本时，将原文不改动地保存为 UTF-8 临时文本；doc、docx、pdf 或图片直接使用原文件。
2. 调用技能目录中的 `scripts/legal_review.py prepare`；同一任务有多个文件时优先一次传入全部文件，减少重复解析。
3. 读取上下文的 `documents`。每项含 `source`、`text`、`textSha256`、`citations` 和 `ruleIssues`。逐份阅读全文，复核错别字、病句、结构和序号，并补充脚本未命中的明确问题与非标准法条引用。
4. 有法条引用时，合并全部文书的引用后调用一次 `laws` 批量核验；没有引用时跳过。结合核验结果检查事实冲突、数值核算和论述逻辑，去重后输出确定错误。

不得使用 curl 或自行拼接 multipart 请求。`prepare` 成功后以返回的 `text` 为检查依据，不重复解析同一文件。脚本返回 `auth_required` 时读取 [认证与安全](authentication.md)，登录成功后重试原命令；其他失败直接报告实际错误，不猜测内容或法条。

不创建工作日志、过程报告或复盘文件。平台自动产生的内部日志不属于本技能输出。中间文件放在操作系统的当前任务私有临时目录，不放共享项目目录。为等待用户确认修正版，可以暂时保留检查上下文；用户拒绝修改或修正版交付完成后立即删除临时文本、上下文、法条结果和问题 JSON，不删除用户原文件。

## 脚本命令

从技能根目录执行命令；当前目录不在技能根目录时使用 `legal_review.py` 的绝对路径。输入和输出都传已经确认的绝对路径，输出路径必须是尚不存在的新文件，不得与原文件、上下文或问题 JSON 相同。Windows 不使用虚构的 `/tmp` 路径，优先使用 `python`。

一个或多个法律文件：

```bash
python scripts/legal_review.py prepare --files "<文件1绝对路径>" "<文件2绝对路径>" --output "<临时目录>/review-context.json"
```

用户粘贴文本：

```bash
python scripts/legal_review.py prepare --text-file "<UTF-8临时文本>" --output "<临时目录>/review-context.json"
```

一次批量查询所有法条：

```bash
python scripts/legal_review.py laws --context "<临时目录>/review-context.json" --output "<临时目录>/law-results.json"
```

如果第一遍对自动引用做了任何增加、删除或法名、条号修正，将最终引用列表保存为 JSON 后执行：

```bash
python scripts/legal_review.py laws --queries "<临时目录>/law-queries.json" --output "<临时目录>/law-results.json"
```

`--queries` 与 `--context` 二选一。只有自动引用完全未调整时才使用 `--context`；只要增加、删除或修正过任何一项，就必须使用保存最终列表的 `--queries`。脚本负责最终去重；不要先查询自动提取项，也不要为每条法条分别运行命令。每项必须同时包含 `lawName` 和 `articleNumber`，批量检查不请求整部法律全文。

第一遍还要确认 `citations` 中的书名号标题确属法律、司法解释或其他规范性文件，删除合同、协议和内部制度条款。原文只写“相关规定”或缺少法名、条号时，不猜测补全，也不提交查询；作为未核实项单独说明。

`prepare` 会检查身份证号、统一社会信用代码、明确标注的手机号和银行卡号、日期、模板占位符、高置信度错词及成对标点。上下文返回每份文书的文本、引用和候选问题；候选问题使用原文和字符位置定位。脚本结果是候选问题，最终输出前结合原文复核，避免把脱敏号码、匿名化内容或合法序号误报为错误。

单个文件解析失败时读取 `itemErrors`，继续检查成功文件。`laws` 返回 `status=partial` 时读取对应 `itemErrors` 并说明未核实项；核验未完成不等于文书无误或存在法条错误。

`source.ocrFallbackReason` 或 `source.ocrWarning` 非空时先向用户简要说明 OCR 降级；这不是文书错误，不计入错误数量。

## 法条错误

- 逐字比对法名、条号、款、项、正文、数字和标点。
- 检查法条是否存在，引用是否被改写、删减或拼接。
- 只有 `statusText=有效` 才能作为现行依据；已修改、废止或尚未生效必须提示。
- 检查新旧版本混用，以及把司法解释、行政法规或地方规定误称为法律。
- 支持并精确区分“第十条”和“第十条之一”等增设条文。同一法条问题出现多次时只解释一次，并列出全部位置。
- 法条正确时不输出法名、条文、版本或“核验无误”等内容。

## 文字与形式检查

第一遍阅读全文同时完成以下类别并补充非标准法条引用，不为每个类别重新扫描全文：

1. 错别字：明确错字、OCR 错字和错误法律术语。
2. 病句：成分残缺、搭配不当、语序混乱、指代不明、句式杂糅和明确标点错误。
3. 结构错误：当前文书类型必要部分缺失、内容错位、请求与理由没有对应结构。
4. 序号错误：同层级重号、跳号、倒序、层级混乱和交叉引用错误。

不输出写作风格偏好，不把“可以润色”“可以更充分”当作错误。脚本和 Agent 命中同一位置时合并为一项。

## 上下文检查

第二遍阅读全文检查事实、数值核算和论述，不再复查法条、错别字、格式或序号。

事实错误限于文书内部可以证明的问题：主体姓名或身份冲突，同一日期、金额、数量前后矛盾，事件顺序不可能，证据名称或编号无法对应，以及号码规则明确校验失败。没有外部证据时只指出两处表述冲突，不擅自判断哪一处事实为真。

### 数值核算

对文书内由已载明前提可以确定的数值关系完成核算，包括金额、面积、数量、比例、倍数、单价、合计、差额、利息和期间折算。数字密集文书必须完成此项；身份证号码、案号、地址门牌号和没有可计算关系的孤立数字无需单独核算。

核对同一数值在不同位置是否一致，并核对单价乘数量、分项合计、比例或倍数换算、本金乘利率乘明确期间等直接关系。只使用文书明确写出的单位、期间、计息方式、计算口径和四舍五入规则；缺少必要前提时内部标记为“无法根据文书内容核算”，不猜测、不认定为错误，也不进入最终错误列表。

数值核算正确时不输出核算过程或“核算无误”。只有确定的算术错误、单位错误、前后金额矛盾或计算前提与结果不一致，才按问题性质归入事实错误或论述错误，并给出最小修改。

论述错误限于明确逻辑问题：结论与现行法条冲突，事实不能推出结论，请求没有对应事实或法律依据，前提与结论矛盾，同一文书作出互斥主张，以及法条适用条件与文书事实不对应。不评价诉讼策略优劣。

## 去重与停止条件

- 维护内部问题表，字段至少包含类别、起止位置、原文、问题、修改内容和修改状态。
- 相同位置和相同修改只保留一次；同一错误多处出现时合并位置。
- 同一位置命中多个类别时按“法条、错别字、病句、结构、序号、事实、论述”的优先级归类，其他原因并入同一项。
- 只有确定错误进入最终结果；纯猜测和一般性建议不输出。
- 完成一次文字与形式检查、一次批量法条核验和一次上下文检查后立即停止，不以“可能仍有遗漏”为由重新从头检查。

## 输出格式

只用普通编号输出错误，跳过没有错误的类别：

```text
共发现 3 处错误：

1. 《起诉状.docx》，法条错误
原文：“……”
问题：……
应改为：“……”

2. 《起诉状.docx》，错别字
原文：“权力人”
应改为：“权利人”

3. 《起诉状.docx》，事实错误
问题：两处付款日期不一致。
修改方式：请根据付款凭证确认正确日期。
```

不输出正确内容、零问题类别、检查步骤、正确数量、风险等级或整段重写。法条错误可以附接口依据；其他错误只写定位、问题和最小修改。敏感号码使用脱敏值。

发现至少一处错误时，最后固定输出：

```text
是否需要我输出修改错误后的完整版本？（只改错误之处，其余一字不差）
```

没有错误且不存在未核实项时只输出“未发现明确错误。”，不询问修正版。存在接口失败或未核实项时，先列出未完成核验的项目；其余部分只能表述为“已完成部分未发现明确错误”。

## 生成完整修正版

用户确认后，只为具有确定替换值的问题生成修改数组；每个确认修改项必须显式包含 `"apply":true`、`"replacementStatus":"ready"` 和 `replacement`，再执行：

```bash
python scripts/legal_review.py apply --context "<临时目录>/review-context.json" --document-number <文书序号> --issues "<临时目录>/accepted-issues.json" --output "<输出路径>/修改后完整版本.txt"
```

生成 `accepted-issues.json` 时必须使用如下对象结构，其中 `textSha256` 原样复制自 `review-context.json`；每项修改必须替换至少一个已存在字符，缺字或缺标点通过替换相邻的已存在文本表达，不使用空位置插入。

```json
{
  "textSha256": "<review-context.json 的 textSha256>",
  "issues": [
    {"apply": true, "replacementStatus": "ready", "start": 0, "end": 2, "original": "错字", "replacement": "正字"}
  ]
}
```

脚本一次拼接完成全部替换，校验整数位置、原文、重叠范围、上下文摘要和未修改区域，并以排他方式写入新文件；即使目标在检查期间被其他进程创建也不会覆盖。身份证号、冲突日期或未知事实没有正确值时，先向用户询问，不猜测。直接粘贴的文本可以保证错误之外逐字不变；文件解析后只能保证解析文本逐字不变，不能承诺原 docx 底层版式不变。
