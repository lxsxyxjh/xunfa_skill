# 法保科技工作流

通过法保科技接口完成法律文件解析、法条核验、法律文书起草、生成和审查。先核实原始材料与现行法依据，再形成结论或交付文件。

## 强制规则

1. 只要任务包含法律内容或法律文件，先使用本技能路由，再执行具体操作。
2. 法律 doc、docx、pdf 和图片必须通过文件解析接口读取；扫描件由服务端自动 OCR。
3. 法条原文和时效性必须通过法律检索接口取得，禁止凭记忆复述，也不得把搜索摘要当作法条原文。
4. 法律文书 docx 的生成和复核必须使用本技能，不得用通用文档工具替代。
5. 接口失败时报告实际错误，不猜测文件内容、法条原文、时效状态或生成结果。
6. 任何密钥、密码和登录凭据都不得出现在日志、文档或答复中。
7. 检查法律文书时直接执行 `scripts/legal_review.py` 完成文件解析、规则预检和批量法条查询；正常执行不读取脚本源码，不使用 curl，不回读已经解析成功的原文件。
8. 起草起诉状、答辩状、申请书、代理意见、质证意见、开庭提纲、证据目录或其他法律文书时，必须读取法律文书起草参考；不得凭通用写作习惯替代其中的文书类型、论证和输出规则。

## 任务路由

根据任务只读取所需参考文件：

- 登录、token 读取与秘密保护：读取 [认证与安全](references/authentication.md)。
- 读取、OCR、提取或总结法律文件：读取 [法律文件解析](references/file-parsing.md)。
- 查询法律全文、法条原文或核验时效性：读取 [法律检索与核验](references/law-retrieval.md)。
- 起草起诉状、答辩状、申请书、代理意见、质证意见、开庭提纲、证据目录或其他法律文书：读取 [法律文书起草](references/document-drafting.md)。
- 把纯文本生成标准法律文书 docx：读取 [法律文书生成](references/document-generation.md)。
- 审查合同、诉状、判决书或其他法律文书：只读取 [法律文书检查](references/document-review.md) 并执行其中脚本；认证失败时才读取认证参考，其他接口失败不再加载接口说明或重复试探。

同一任务按实际需要组合参考流程。通常先解析材料或接收事实，再核验需要引用的法条，最后起草、分析、检查或生成交付文件；固定模板未覆盖的文书使用法律文书起草参考中的通用规则。法律文书检查以专项参考流程为准。

## 通用调用约定

- 默认服务地址为 `https://fabaotu.com`；仅在用户明确指定本机开发服务时使用 `FABAO_BASE_URL` 覆盖，脚本拒绝其他远程主机和正式服务的明文 HTTP。
- 使用当前 Agent 可用的 HTTP 能力发送请求，不依赖特定平台的工具名称或命令行环境。
- 除文书生成接口外，业务响应统一为 `{"code":"...","msg":"...","data":...}`，只有 `code=="1"` 表示成功。
- 整体请求成功不等于每个文件或每条数据成功；必须检查具体项目的错误字段。
- 需要登录时按认证参考执行，登录完成后只重试原业务请求一次。
- 只读取当前任务直接需要的参考文件，不一次加载全部接口说明。

## 输出要求

- 法律分析引用法条时，列明法律名称、条号、接口返回的原文和时效状态；法律文书检查以专项输出规则为准，正确法条不输出。
- 文件 OCR 发生降级时，向用户说明实际识别来源、降级原因和警告，但不展示任何 OCR 凭据。
- 无法从接口核实的内容明确标为“未核实”，不得以模型知识补齐。
- 接口产生文件时返回实际文件或可访问链接，不声称尚未生成的文件已经完成。
